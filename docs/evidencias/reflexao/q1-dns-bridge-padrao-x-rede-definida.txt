# Gerado em: 2026-10-20T10:46:04-03:00 | Projeto Compose: achados-perdidos-experimentos
# Nota: Porta do host usada neste teste: 18080 (a 8080 estava ocupada por outro programa nesta máquina; o docker-compose.yml entregue publica 8080 e foi executado sem alterações, apenas com override de porta).

# Resolução feita com `getent hosts` (resolvedor da libc): ele respeita a lista de domínios de busca do host. O `nslookup` do BusyBox
# acrescenta o domínio de busca do host (ex.: *.cloudapp.net no GitHub Actions) e não tenta o nome puro, o que dá falso NXDOMAIN.

# A) Rede bridge PADRÃO (docker run sem --network): sobe um contêiner e tenta resolver o nome dele a partir de outro.

$ docker run -d --name achados-perdidos-exp-q1-a alpine:3.24 sleep 300
d5c76b1662f8994e67180a3389d7c9cbf6a7656757c1f76e0c168ed08da053a0

$ docker run --rm alpine:3.24 cat /etc/resolv.conf
# Generated by Docker Engine.
# This file can be edited; Docker Engine will not make further changes once it
# has been modified.

nameserver 192.168.65.7

# Based on host file: '/etc/resolv.conf' (legacy)
# Overrides: []

$ docker run --rm alpine:3.24 getent hosts achados-perdidos-exp-q1-a

[código de saída: 2]

# (código de saída do getent acima: 2; 2 = nome não encontrado)

# B) Rede DEFINIDA PELO USUÁRIO (como a rede_interna do Compose): o mesmo teste.

$ docker network create achados-perdidos-exp-q1-rede
